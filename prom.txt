
# 모멘텀 봇 — 세션 인계 프롬프트 (2026-05-14)

## 프로젝트 개요
Bybit 데모 계좌에서 5분봉 모멘텀 전략을 자동 매매하는 봇.
전략 핵심: 5분봉 return이 rolling top 3%(97 percentile) 초과 시 같은 방향 진입 (Big Move Follow-Through).

--------------------------------------------------------------

## v1 → v2 전환 배경

### v1 실패 요약 (2026-05-12 14:11 ~ 05-13 09:00, 약 19시간)
- 78거래, 승률 25.6% (20W/58L), PnL -$8,974, Profit Factor 0.382
- 설계 RR 1:2인데 실제 RR 1.05 — TP(6×ATR)가 너무 멀어 도달 못함
- SL(3×ATR)에서 대부분 끊기고, 이후 원래 방향으로 가는 패턴
- Whipsaw 심각: 같은 심볼 양방향 반복 손절 (INJUSDT 7건 14% 등)
- Long 승률 18.4%로 특히 심각 (BTC 하락 추세에서 long 모멘텀)
- 시간대 편향: UTC 21-22시 14건 승률 0% (-$4,066), UTC 00-03시 12건 승률 83% (+$1,888)
- 43코인 유니버스 vs 6코인 백테스트 → edge 없는 심볼에서 무차별 진입

### v2 설계 의도
v1 실패 원인 분석 후, **수익이 아닌 데이터 수집 목적**으로 v2 개발.
최소 200건의 깨끗한 거래 표본을 모아 코인별/시간대별/방향별/신호강도별 분석 후 v3 방향 결정.
"어떻게 박살나는지" 자체가 분석 데이터이므로, 필터/안전장치 의도적으로 미적용.

## v2 파라미터 (v1 대비 변경점)

| 파라미터 | v1 | v2 | 변경 이유 |
|----------|----|----|-----------|
| SL | 3.0×ATR | 1.5×ATR | v1에서 SL 너무 커서 손실 단가 높음 |
| TP | SL×2.0 (=6×ATR) | SL×1.33 (=2×ATR) | v1 TP 도달률 극히 낮음 → 현실적 수준으로 |
| Max Hold | 36 bars (3시간) | 12 bars (1시간) | 장기 보유 시 되돌림 피해 |
| Daily loss cap | 있음 | **제거** | 데이터 수집 목적, 의도적 |

유지된 파라미터:
- Signal: 97 percentile, threshold window 2000 bars
- ATR period: 20
- Cooldown: 12 bars (1시간)
- Max positions: 10
- Risk: 0.5%/거래
- Leverage cap: 3x (실효)
- Universe: min $20M volume, 자동 스캔 (30~60개)

### ⚠️ 절대 추가 금지 (데이터 수집 기간 동안)
코인 유니버스 축소, 시간대 필터, 일일 손실 한도, 연속 손실 중단, 추세 필터, 변동성/거래량 필터, cooldown 연장 — 전부 금지.

## v2에서 수정한 코드

### momentum_config.yaml
- SL/TP/Hold 파라미터 변경, daily_loss_pct 설정 제거

### momentum_bot.py — 주요 변경
- **OpenPosition 필드 확장**: trade_id, atr_at_entry, signal_strength, signal_return_pct, btc_price_at_entry, btc_1h_change_pct, position_size_usd, mfe, mae
- **_fetch_all_tickers()**: 배치 티커 1회 호출로 API 절약 (기존 코인별 개별 호출 → 전체 1회)
- **_get_btc_data()**: BTC 현재가 + 1시간 변동률 (price_map 재활용)
- **_update_mfe_mae()**: 캔들 캐시 high/low 기반 intra-bar MFE/MAE 추적
- **_manage_positions()**: 오픈 포지션 캔들 매 bar 갱신 + MFE/MAE 추적 + exit_reason(SL/TP/Timeout) 분류
- **_log_trade()**: 23개 필드 JSONL 로깅
- **_sync_clock_offset()**: Bybit 서버 시계 offset 자동 보정 (pybit monkey-patch)
- **from_dict()**: 기존 v1 state 호환성 방어
- Daily loss cap 체크 로직 제거

### strategy/momentum.py
- MomentumSignal에 percentile_rank 필드 추가
- feed_candle()에서 실제 percentile rank(0-100) 계산하여 반환

### scripts/analyze_trades.py (신규)
- v2 거래 데이터 분석 스크립트 (시간대별/방향별/심볼별 PnL 분석)

## 해결된 이슈 (참고)

1. **Windows cp949 인코딩** → config YAML 로드 시 `encoding="utf-8"` 명시
2. **Bybit 시계 offset (~3초)** → `_sync_clock_offset()` + pybit timestamp monkey-patch
3. **MFE/MAE 해상도** → lastPrice 대신 캔들 high/low 사용, 오픈 포지션 캔들 매 bar 갱신
4. **signal_strength 정의 오류** → threshold 값 대신 percentile rank(0-100)로 수정
5. **API 과다 호출** → `_fetch_all_tickers()` 배치 1회 + price_map 재활용
6. **qty 부동소수점 오류** → Decimal 사용으로 수정
7. **다른 PC에서 venv 재생성** → `venv` 삭제 후 `python -m venv venv` + `pip install -r requirements.txt` + `pip install -e .`

## 알려진 제약/참고

- **API rate limit**: 유니버스 30~60개 코인 kline 개별 호출 → 가끔 Bybit rate limit 에러 발생 (ErrCode 10006). pybit 자동 재시도(2초 sleep)하므로 데이터 유실 없음. 심각하지 않음.
- **v1 vs v2 signal_strength 비호환**: v1은 threshold 값(절대값), v2는 percentile rank(0-100). 두 데이터셋 합산 분석 시 주의.
- **봇 재시작 시**: state_momentum.json에서 오픈 포지션 복원됨. 캔들 캐시는 재구축.
- **PowerShell에서 실행 시**: `&&` 연산자 불가. `;` 으로 명령 구분.
