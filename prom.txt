
# 모멘텀 봇 -- 세션 인계 프롬프트 (2026-05-18)

## 프로젝트 개요
Bybit 데모 계좌에서 5분봉 모멘텀 전략을 자동 매매하는 봇.
전략 핵심: 5분봉 return이 rolling top percentile 초과 시 같은 방향 진입 (Big Move Follow-Through).

## 전문가 분석 요약 (2026-05-15)

v1/v2/v3 전체 335건 데이터를 알고리즘 트레이딩 전문가에게 분석 의뢰. 핵심 진단:

### 전략 현 상태
- "edge는 존재하지만 실행 비용(슬리피지+수수료+진입타이밍)에 먹히는 상태"
- v2+v3 합산 PF 0.864 = 비용 제거 시 PF ~1.05. 미약한 raw edge
- 5분봉 close 후 시장가 진입은 이미 move 완료 후 추격 → HFT의 exit liquidity 제공자가 됨

### RR 미달 원인 (설계 1.33 vs 실현 0.95)
- SL 슬리피지 (시장가 청산, 평균 +0.1~0.5%p)
- 수수료 비대칭 (왕복 0.11%)
- 진입 슬리피지 (시장가 진입)
- → 설계 RR 1.8~2.0이어야 실현 1.3

### 가장 impact 큰 단일 변경 (전문가 추천)
**Pullback entry**: signal 후 0.3 ATR pullback에 limit order 진입, 3 bars 내 미체결 시 취소
- 진입 슬리피지 제거 + MFE=0(꼭대기 진입) 자동 필터링
- PF 0.86 → 1.05~1.15 예상 (fill rate 65% 가정)
- → 옵션 C로 문서화, B 검증 후 적용 예정

- `prompt_expert_analysis.md` — 전문가 분석 의뢰용 프롬프트 (335건 데이터 종합)

## 해결된 이슈 (참고)

1. **Windows cp949 인코딩** -> config YAML 로드 시 `encoding="utf-8"` 명시
2. **Bybit 시계 offset (~3초)** -> `_sync_clock_offset()` + pybit timestamp monkey-patch
3. **MFE/MAE 해상도** -> lastPrice 대신 캔들 high/low 사용, 오픈 포지션 캔들 매 bar 갱신
4. **signal_strength 정의 오류** -> threshold 값 대신 percentile rank(0-100)로 수정
5. **API 과다 호출** -> `_fetch_all_tickers()` 배치 1회 + price_map 재활용
6. **qty 부동소수점 오류** -> Decimal 사용으로 수정

## 알려진 제약/참고

- **API rate limit**: 유니버스 30~60개 코인 kline 개별 호출 -> 가끔 Bybit rate limit 에러 발생. pybit 자동 재시도(2초 sleep). 심각하지 않음.
- **v1 vs v2 signal_strength 비호환**: v1은 threshold 값(절대값), v2/v3/v3.1은 percentile rank(0-100). 두 데이터셋 합산 분석 시 주의.
- **봇 재시작 시**: state_momentum.json에서 오픈 포지션 복원됨. 캔들 캐시는 재구축.
- **PowerShell에서 실행 시**: `&&` 연산자 불가. `;` 으로 명령 구분.
- **재가동 전 반드시 시계 동기화**: `w32tm /resync /force` (PowerShell 관리자)
