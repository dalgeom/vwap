## 3. 현재 전략 — Funding Contrarian (펀딩 역추세)

### 핵심 원리
"펀딩비가 극단적 = 시장 참여자 포지셔닝이 한쪽으로 과열 = 8시간 안에 가격이 반대로 움직일 확률이 높음"

### 3.1 동작 흐름

1. 8시간마다 펀딩 정산 시점(00/08/16 UTC)에 실행
2. 기존 포지션 전부 시장가 청산
3. 15개 코인 펀딩비 조회
4. |펀딩| > 0.025% 코인 필터, 절댓값 큰 순 정렬
5. 상위 최대 5개에 역방향 limit order 진입
6. 8시간 뒤 다음 펀딩 시점에 반복

### 3.2 설정값

| 항목 | 값 |
|------|----|
| 진입 조건 | \|펀딩비\| > 0.025% |
| 방향 | 양의 펀딩 → 숏, 음의 펀딩 → 롱 |
| SL | 1.0 ATR(14) |
| TP | 없음 (8h 후 시장가 청산) |
| 동시 포지션 | 최대 5개 (분산) |
| 같은 방향 | 3개 초과 시 사이즈 50% 감소 |
| 거래당 리스크 | 0.5% |
| 실효 레버리지 | 최대 3배 캡 |
| 레버리지 설정 | 5x |
| 진입 방식 | Limit order (30초 대기 x 3회, 미체결 시 스킵) |
| 일일 손실 한도 | -2% → 24h 정지 |
| 주간 손실 한도 | -5% → 7일 정지 |
| 월간 손실 한도 | -10% → 30일 정지 |
| 일일 최대 거래 | 10건 |
| 펀딩 윈도우 | 3분 (초과 시 진입 스킵) |

### 3.3 유니버스 자동 갱신

- 시점: 봇 시작 + 매주 월요일 00:00 UTC
- 기준: Bybit USDT 선물, 24h 거래대금 $50M+, BTC/ETH 제외, 펀딩 간격 8h만, 상위 15개
- 저장: `data/universe.json`

### 3.4 안전장치

- 고아 포지션 방지: 시작 시 9h 초과 포지션 즉시 청산
- 거래소-state 동기화: 시작 시 reconciliation (API 50%+ 에러 시 봇 종료)
- heartbeat: 30초마다 갱신 (외부 watchdog용)
- 비상 정지: `data/STOP` 파일 생성 시 전체 청산 후 종료
- 슬리피지 로깅: `data/slippage.jsonl` (0.15% 초과 시 경고)

## 7. 실전 전환 로드맵

### Stage 2: 데모 운영 (현재, 4주)
- 목적: 코드 안정성 검증, 백테스트 정합성 확인
- 모니터링: 봇 재시작 0회, 펀딩 윈도우 놓침 0회, state mismatch 0회

### Stage 3: 소액 실거래 ($1K, 8주)
- 변경: `demo=False`, 슬리피지 실측
- 기준: 백테스트 가정(0.20%)과 실측 슬리피지 차이 < 1.5배

### Stage 4: 자본 증가
- W1-2: $1K → W3-4: $3K → M2: $10K → M3-6: $30K
- Capacity 한계: $200K~500K

### GO 기준 (데모 4주 후)
- P0: 봇 재시작 0회, 펀딩 놓침 0회, state 불일치 0회
- P1: 거래수 일 1~4건, 청산 사유 분포 백테스트와 일치
- P2: PnL/승률이 백테스트 ±50% 범위

### 전략 사망 판정 (실거래 중)
- 60일 rolling Sharpe < 0.5
- 100거래 승률 < 40%
- 월간 누적 수익률 < 0% 3개월 연속
