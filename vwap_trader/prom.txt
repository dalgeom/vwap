이전 PC에서 봇을 중단하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션·bar_counter·cooldown이 들어 있다. pull 안 하면 포지션 추적이 어긋난다.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC 봇이 완전히 죽었는지 먼저 확인.
3. 시계 동기화(관리자 PowerShell): `w32tm /resync /force` — PC 재부팅 직후엔 필수(ErrCode 10002 방지).
4. 재가동: **`cd vwap_trader; .\venv\Scripts\python.exe -m vwap_trader.momentum_bot`** — ★ **`cd vwap_trader` 필수**(venv는 `vwap_trader/venv`, git root는 한 단계 위 `code/`). 경로 앞 `.\` 빠뜨리면 PowerShell이 인식 못 함.
5. 로그에 `State loaded: N positions, bar=...` 확인. 포지션은 Bybit 서버에 살아있으니 봇 꺼진 동안에도 SL 작동.
6. **★ 정전/크래시 후 재가동이면 reconcile 확인 필수**: 봇은 기동 시 거래소와 자동 대조를 안 한다. state 포지션 수 ↔ 거래소 실제 오픈 포지션(`get_positions` category=linear, settleCoin=USDT)을 symbol+qty로 대조. 어긋나면 orphan(거래소만)/phantom(state만) 처리. ※ 진입+SL은 atomic(`place_order`에 stopLoss 동봉)이라 orphan도 무방비는 아님.

## 1. 프로젝트 개요
- **위치**: `vwap_trader/`, Windows + PowerShell, venv `vwap_trader/venv/`. **git root는 한 단계 위(`code/`)**.
- **봇**: Bybit USDT 무기한 선물 **데모 계좌**, 모멘텀 추종.
- **버전 v5.1+**: 1h봉 + BE+Trailing + 1m 폴링 + Tier Cap + Clock Resync + 신호컨텍스트 로깅 + Shadow Log + **entry_price 실체결가 기록(2026-06-04 수정)**.
- **핵심 원리**: 1h봉 abs(return)이 과거 500봉 99.5%ile 초과 시 그 방향 진입.
- **현 단계**: 데이터 수집 + 손실 원인 연구. 검증 임계점 50건(통과)·**200건(Go/No-Go, 현재 95)**.

## 4. 이번 세션(2026-06-02~04) 핵심

### 4.1 ★ entry_price 버그 수정 (코드 변경 — 데이터 무결성, 이번 커밋 포함)
- 증상: Bybit `place_order` 응답엔 avgPrice 필드가 없는데 코드가 이를 읽으려다 항상 0 → `entry_price`가 **신호가(직전 1h봉 종가)로 fallback**. 변동성 큰 막차일수록 실체결가와 괴리(H: 신호가 0.544 vs 실체결 0.555, +2% 슬리피지).
- 3대 영향: ① slippage 로그 전부 0(무용) ② state/live entry·pnl 부정확 ③ **BE/trail floor가 신호가 기준이라 실제 본전 아님**(실매매 손해).
- 수정([momentum_bot.py `_fetch_actual_entry`]): 시장가 직후 0.4s 대기 후 `get_positions`로 실 avgPrice 읽어 entry로 사용(실패 시 신호가 fallback). positionIdx Buy=1/Sell=2. **bar265+ 진입부터 state entry == 거래소 avgPrice 0.00% 검증됨.** 과거 데이터·기존 포지션 무영향.

### 4.2 ★ 93건 corrected 통계 분석 (peeking 아님 — 사전등록 가설 지지 정황)
- **hold≤2(즉사권) 43건: WR 11.6%, EV −$77 / hold≥3 50건: WR 62%, EV +$104** → H1(adverse selection) 강력 확증. 손실의 원천 = 진입 직후 역행.
- **exit별**: TrailSL 32건 +$6,357(생명줄) / SL 51건 −$4,880 / BE 7건 −$137 / Timeout 3건 +$560.
- **방향**: long EV +$27 > short EV +$6. **regime**: DOWN/FLAT_HIGH(PF 1.8~2.1) > UP_HIGH(1.14). UNKNOWN 6건은 콜드캐시 오염(기지).
- ★ **|sigret| 비선형**: <10 EV+$8.8 / **10–20 EV+$90(sweet spot)** / ≥20 EV−$5(극단=손해 편향). 단 극단 구간에 잭팟(+540) 섞임.

### 4.3 I6 등록 + 백테스트 부결 (§11)
- "극단 sigret 상한/축소"를 §11 v6 개입후보 **I6**로 등록. 백테스트(93건 단순제거) 결과: **컷 위치에 결과 극도 민감(+2334~+648) = overfitting, 잭팟이 컷 경계 산재 → n93 부결, 200건 재검증.** 단순컷이 안 통한다는 실증.

## 5. 미해결/우선순위 (냉철한 순서)
1. **데이터 축적이 1순위.** 판단 지점 = **극단막차(abs ret24>50) ~20건** 또는 **총 200건**(현재 95) 중 먼저 닿는 쪽. 그 전엔 필터/exit 적용 금지(잭팟·sweet spot 죽임). I6 부결이 그 증거.
2. **shadow 누적**(현재 36건, short_cap 쏠림) — H13/H5는 (a)klines 소급 pnl 인프라 (b)reason별 충분누적 후 가능. 장기.
3. 검증 후: exit 튜닝(H2/I1·I2·I3, EDGE처럼 고변동 BE 트리거 너무 멂), regime 게이팅(H3/H9), 극단 sigret(I6).
4. ⚠️ **peeking·다중비교 경계**: 93건에서 그럴듯한 컷 찾기 = 데이터마이닝. 사전등록 가설만, 200건 일괄검정. 라이브 파라미터 임계까지 고정.
