이전 PC에서 봇을 graceful 종료(Ctrl+C)하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션·bar_counter·cooldown이 들어 있다. pull 안 하면 포지션 추적이 어긋난다.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC 봇이 완전히 죽었는지 먼저 확인.
3. 시계 동기화(관리자 PowerShell): `w32tm /resync /force` — PC 재부팅 직후엔 필수(ErrCode 10002 방지).
4. 재가동: **`cd vwap_trader; .\venv\Scripts\python.exe -m vwap_trader.momentum_bot`** — ★ **`cd vwap_trader` 필수**(venv는 `vwap_trader/venv`, git root는 한 단계 위 `code/`). 경로 앞 `.\` 빠뜨리면 PowerShell이 인식 못 함.
5. 로그에 `State loaded: N positions, bar=...` 확인. 포지션은 Bybit 서버에 살아있으니 봇 꺼진 동안에도 SL 작동.
6. **★ 정전/크래시 후 재가동이면 reconcile 확인 필수**: 봇은 기동 시 거래소와 자동 대조를 안 한다. state 포지션 수 ↔ 거래소 실제 오픈 포지션(`get_positions` category=linear, settleCoin=USDT)을 symbol+qty로 대조. 어긋나면 orphan(거래소만)/phantom(state만) 처리. ※ 진입+SL은 atomic(`place_order`에 stopLoss 동봉)이라 orphan도 무방비는 아님.
7. **★ 분석 전 `rebuild_pnl.py` 재실행**: live jsonl pnl은 버그 오염값. 분석은 항상 `trades_momentum_corrected.jsonl`(거래소 closed-pnl 재구축). **단 §6 unmatched는 직접 보정 필요.**

## 1. 프로젝트 개요
- **위치**: `vwap_trader/`, Windows + PowerShell, venv `vwap_trader/venv/`. **git root는 한 단계 위(`code/`)**.
- **봇**: Bybit USDT 무기한 선물 **데모 계좌**, 모멘텀 추종.
- **버전 v5.1+**: 1h봉 + BE+Trailing + 1m 폴링 + Tier Cap + Clock Resync + 신호컨텍스트 로깅 + Shadow Log + entry_price 실체결가 기록(06-04) + **closed-pnl freshness 매칭 수정(06-05)**.

## 4. 이번 세션(2026-06-05) 핵심

### 4.1 ★ closed-pnl 옛레코드 오매칭 버그 발견·수정 (코드 변경, 이번 커밋 포함)

- 근본원인: `_get_closed_pnl_record`가 side+entry±1%+qty±1%로 매칭하는데, 같은 심볼 2거래(STG short 06-02 entry 0.31155 vs 06-04 0.3092 = **0.76% 차**)가 **둘 다 1% 허용오차 통과**. 청산 직후 신선 레코드 미전파 상태에서 옛 레코드만 존재 → matches 비어있지 않아 retry 없이 즉시 옛 레코드 반환. **loose 1% 매칭 + 전파지연 조합.** (entry_price 버그를 잡은 첫 수정의 잔여 결함.)
- 수정([momentum_bot.py `_get_closed_pnl_record`]): **freshness 게이트** — closed-pnl 레코드의 `createdTime >= 진입시각(pos.entry_time ms)`인 것만 매칭. 옛거래(타 거래 진입 전 청산) 자동배제, 신선 레코드 미전파 시 matches 비어 retry 정상작동. **실증검증은 미래 동일심볼 반복거래 청산 때** 로그 `Closed PnL matched ...(try N)`로.

## 5. 미해결/우선순위 (냉철한 순서)
1. **데이터 축적이 1순위.** 판단 지점 = **극단막차(abs ret24>50) ~20건** 또는 **총 200건**(현재 106) 중 먼저 닿는 쪽. 그 전엔 필터/exit 적용 금지(잭팟·sweet spot 죽임). I6 부결이 그 증거.
2. **shadow 누적**(현재 ~65줄) — H13/H5는 (a)klines 소급 pnl 인프라 (b)reason별 충분누적 후 가능. 장기.
3. 검증 후: exit 튜닝(H2/I1·I2·I3, EDGE처럼 고변동 BE 트리거 너무 멂), regime 게이팅(H3/H9), 극단 sigret(I6).
4. ⚠️ **peeking·다중비교 경계**: corrected에서 그럴듯한 컷 찾기 = 데이터마이닝. 사전등록 가설만, 200건 일괄검정. 라이브 파라미터 임계까지 고정.
