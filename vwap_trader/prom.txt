이전 PC에서 봇을 graceful 종료(STOP_MOMENTUM 또는 Ctrl+C)하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션·bar_counter·cooldown이 들어 있다. pull 안 하면 포지션 추적 어긋남.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC 봇이 완전히 죽었는지 먼저 확인.
3. 시계 동기화(관리자 PowerShell): `w32tm /resync /force` — 재부팅 직후 필수(ErrCode 10002 방지).
4. 재가동: **`cd vwap_trader; .\venv\Scripts\python.exe -m vwap_trader.momentum_bot`** — ★ **`cd vwap_trader` 필수**(venv는 `vwap_trader/venv`, git root는 한 단계 위 `code/`). 경로 앞 `.\` 빠뜨리면 PowerShell 인식 못 함.
5. 로그 `State loaded: N positions, bar=...` 확인. 포지션은 Bybit 서버에 살아있어 봇 꺼진 동안에도 SL 작동.
6. **★ 정전/크래시 후면 reconcile 확인**: 봇은 기동 시 거래소와 자동대조 안 함. state 포지션 ↔ 거래소 실제오픈(`get_positions` category=linear, settleCoin=USDT)을 symbol+qty로 대조. 진입+SL은 atomic(place_order에 stopLoss 동봉)이라 orphan도 무방비 아님.
7. **★ 분석 전 `rebuild_pnl.py` 재실행**: live jsonl pnl은 과거분 오염. 분석은 항상 `trades_momentum_corrected.jsonl`. 단 §6 unmatched는 직접 보정(§8.7). ⚠️ rebuild는 corrected 전체를 덮어써 HUSDT 수동보정이 되돌아감 → **신규 소수건 분석은 거래소 closed-pnl 직접대조가 더 안전**(이번 세션도 그렇게 함).

## 4. 이번 세션(2026-06-07~08) 핵심
### 4.1 심층 자아성찰 분석 (n124) — 잭팟 의존은 구조다
- 누적 **06-01 정점 +$2,025 → 06-07 +$741**(6일 drawdown=잭팟 가뭄, BEAT로 일부 회복). 순엣지 얇음(승합 +8,170/패합 −7,429), **top5 winner가 전체 승리 43%**.
- **사용자 질문 "왜 잭팟의존? steady-up 불가?"에 데이터로 답**: ① 패자 80건 중 **즉시역행(MFE<0.5%) 46건 −$4,799 = 손절튜닝으로 불가**(진입 즉시 틀림) vs green→red 28건 −$2,211=구제가능. ② 하드TP 시뮬: 모든 익절선이 +$741→음수(잭팟 절단). ③ 진입필터로 패자 선별 불가(§8.5 473건). ④ 전면 반전=잭팟이 대참사로. **결론: "조금씩 꾸준히"=mean-reversion(다른 전략, 숨은 파국꼬리). 추세추종은 본질적으로 잭팟형. 출혈은 줄일 수 있어도(F1) 구조는 못 바꿈.**

- ※ 거래소 private 조회: `config/.env` 키로 `pybit HTTP(demo=True)`. 키 출력·커밋 금지. 봇은 정각(분=0) 무거운 scan → 분석 API는 정각 피해서. 임시 스크립트는 쓰고 삭제.
