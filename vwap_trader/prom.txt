이전 PC에서 봇을 graceful 종료(STOP_MOMENTUM 또는 Ctrl+C)하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션·bar_counter·cooldown이 들어 있다. pull 안 하면 포지션 추적 어긋남.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC 봇이 완전히 죽었는지 먼저 확인.
3. 시계 동기화(관리자 PowerShell): `w32tm /resync /force` — 재부팅 직후 필수(ErrCode 10002 방지).
4. 재가동: **`cd vwap_trader; .\venv\Scripts\python.exe -m vwap_trader.momentum_bot`** — ★ **`cd vwap_trader` 필수**(venv는 `vwap_trader/venv`, git root는 한 단계 위 `code/`).
5. 로그 `State loaded: 3 positions, bar≈486` 확인(인계 시점 기준, 그 사이 변동 가능). 포지션은 Bybit 서버에 살아있어 봇 꺼진 동안에도 SL 작동.
6. **★ 정전/크래시 후면 reconcile 확인**: state 포지션 ↔ 거래소 실제오픈(`get_positions` category=linear, settleCoin=USDT)을 symbol+qty로 대조. 진입+SL은 atomic이라 orphan 무방비 아님. (06-11 VELVET 청산 3분 지연도 봇이 자체해소함=정상.)
7. **★ 분석 전 `rebuild_pnl.py` 재실행**: live jsonl pnl은 과거분 오염. 분석은 항상 `trades_momentum_corrected.jsonl`. **⚠️ 인계 직전 VELVET 청산 pnl이 ESTIMATED(+$1,386)로 기록됨**(거래소 정산 전파지연, 실값 +$1,359) → rebuild로 정정 필요. 단 rebuild는 corrected 전체 덮어써 수동보정(§8.7 HUSDT)이 되돌아감 → 신규 소수건은 거래소 closed-pnl 직접대조가 더 안전.

## ★ v7 전환 (2026-06-15, 두 번째 거래로직 변경) — 최신, 반드시 숙지
v6 위에 두 가지 변경(사용자 지시). **코드 커밋됨, 봇 재시작해야 발효.**
- **① 방향별 조건부 정원확장** (`filters.cap_consec_priority: true`): `max_short 3→5`·`max_long 3→4`. 기본 3자리는 무조건, **늘린 자리만 연속성 조건** — short 확장자리=꾸준(consec≥1), long 확장자리=단발(consec0). 근거: `short_cap`/`long_cap` 소급검증(중복제거: short 41건 +97R=꾸준이 +92R / long 22건 +23R=단발이 +22R, **방향별 정반대**, §10·§11 H14). 순수함수 `cap_admits`(모듈) + `self._quick_consec`(L~1373), cap체크는 `_scan_universe`. **롤백: `cap_consec_priority: false` 또는 max를 3/3.** ⚠️ in-sample(forward 0)·동시손실위험(최악24h −$2,183, 단발제외로 완화) → 200건 잠정, peeking 금지.
- **② 거래량 로깅** (`signal_vol_ratio` = 신호봉 거래량/직전20봉평균): 캐시튜플에 volume(인덱스5) 복원 → `compute_vol_ratio`. **기록전용, 거래 무영향.** 신규 진입/shadow부터 축적(과거 소급 안됨). 결론 없음=이제 기록 개시(4번째 진입팩터).
- forward 추적: **`track_cap.py`**(short/long_cap 점수판, 읽기전용, `PYTHONIOENCODING=utf-8 python track_cap.py`). bot_version=v7. 계획서: `docs/superpowers/plans/2026-06-15-v7-cap-volume.md`.

## 4. 이번 세션(2026-06-09~11) 핵심
### 4.1 v6 코드 무죄 3중검증 — 진입가뭄은 시장 탓 (코드 정상)
사용자가 "하루아침에 진입 마름, 코드 문제 아니냐" 의심. 정량 분해로 결론: **신호 원천이 06-06 하루 95건 → 06-07~10 0~2건/일로 붕괴.** F1이 막은 건 v6 전체 **5건뿐**(껐어도 가뭄). 검증: ① F1은 차단해도 shadow 기록→shadow 0=탐지단계서 0 ② 봇로그 scan 정상(Traceback無) ③ 봇코드 우회 독립 klines P99.5 계산: 메이저 6코인 신호 0, H만 5건(탐지정상 반증). **원인=거시 저변동**(웹검색: Fed 긴축·BTC ETF 주간 −$3.4B 유출·미-이란 긴장 → 6월초 −12% 급락 후 유동성 고갈 횡보, 여름까지 지속 전망).
### 4.2 세 팩터 조합분석 (§8.10, 85건) — 사용자 요청
연속성/돈흐름/파도크기 good 이분 8조합. **파도크기(sigret 10~20%)만 단일 흑자, 연속성만·돈흐름만은 적자, 셋 다 good은 0건.** ★ 잭팟이 good 칸에 안 모임(ZEC 셋다bad +629, H 파도bad +648) → 단순 필터 실패 재확인. 칸당 2~6건 극소=사후 탐색, 200건 게이트·데이터마이닝 금지.
### 4.3 track_f1 n=4 — F1 경고등 ON(보류)
F1 차단 4건 would-be 전부 winner(+6.66R). 스크립트 "F1 net NEGATIVE". **단 보류**: n=4·backtest 124건(역추세 net −$657)과 충돌·막힌 4건 전부 극단막차(selection)·path 근사. 역추세 패자 출현 감시, 무변경.
