이전 PC에서 봇을 중단하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션·bar_counter·cooldown이 들어 있다. pull 안 하면 포지션 추적이 어긋난다.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC 봇이 완전히 죽었는지 먼저 확인.
3. 시계 동기화(관리자 PowerShell): `w32tm /resync /force` — Claude가 관리자 권한 elevation으로 직접 실행 가능(UAC 승인 필요). PC 재부팅 직후엔 필수(ErrCode 10002 방지).
4. 재가동: `cd vwap_trader; .\venv\Scripts\python.exe -m vwap_trader.momentum_bot`
5. 로그에 `State loaded: N positions, bar=...` 확인. 포지션은 Bybit 서버에 살아있으니 봇 꺼진 동안에도 SL 작동.
6. **★ 정전/크래시 후 재가동이면 reconcile 확인 필수**: 봇은 기동 시 거래소와 자동 대조를 안 한다. state 포지션 수 ↔ 거래소 실제 오픈 포지션(`get_positions` category=linear, settleCoin=USDT)을 symbol+qty로 대조. 일치하면 OK. 어긋나면 orphan(거래소만)/phantom(state만) 처리. ※ 진입+SL은 atomic(`place_order`에 stopLoss 동봉)이라 orphan도 무방비는 아님. (2026-06-01 정전 시 대조 결과 완전일치였음 — 코드가 안전하게 동작.)

## 4. 이번 세션(2026-06-01) 핵심

### 4.1 Trailing SL spike-retrace 버그 수정 (거래로직 변경 — exit edge case)
- 증상: `best_price`(봉 고점)가 스파이크 후 되밀리면 trail SL(고점−2ATR)이 현재가 위로 → Bybit 10001 거부 → 롤백으로 SL이 초기값에 묶이고 매분 spam.
- 수정([momentum_bot.py `_update_trailing_sl`]): trail이 현재가 침범 시 **entry/BE floor 재확정**(롤백된 SL도 복구). H 0.5121→0.5440 복구 검증됨. **정책=BE-floor**(이익 잠금 욕심 X, 본전만 확보) — 연구단계 "조기컷 금지" 준수.

### 4.2 ★ §11 사전등록 가설 보드 신설 (PLAN 정본)
- OI 단일가설 올인 방지. **Primary 6**(H1 adverse selection·H2 출구 MFE반납·H3 regime비대칭·H4 군집노이즈·H5 배치순위·**H0 NULL**) / **Secondary 8**(H6 OI interaction…H13 shadow반사실) / **v6 개입후보 5**(I1~I5, backtest 필요).
- **규율**: 주지표 EV/총PnL(WR 오도), 200건 일괄검정·peeking 금지, Primary만 confirmatory(Bonferroni). 사후 cherry-pick·데이터마이닝 차단.

### 4.3 OI 가설 반례 누적 (Secondary H6 약화)
- **PORTAL**(OI **+4.3**, 최극단막차 ret24=140) → −9.8% 즉사. **H**(OI **−0.2**) → +20% 최대 winner. "막차+OI↑(실수요)=폭발"의 정반대. §8.5+ "OI 단순부호 변별불가" 재확인. ⚠️ H 오픈/미실현 — peeking 금지, 200건 일괄까지 기록만.

### 4.4 데이터 품질 — regime UNKNOWN 6%(4/65)
- 2건은 옛 거래(version 필드 이전), 2건은 재시작 콜드캐시(BTC 4h 미준비 시 regime=UNKNOWN/btc_4h=0). **연속가동이면 미미 → 보류**(H3/H8/H9 검증에 3% 손실뿐). 안 고침.

## 5. 미해결/우선순위 (냉철한 순서)
1. **데이터 축적이 1순위.** 다음 판단 지점 = **극단막차(abs ret24>50) ~20건** 또는 **총 200건**(현재 66) 중 먼저 닿는 쪽. 그 전엔 필터/exit 적용 금지(weak/극단 winner 죽임).
2. **shadow 누적 느림**(현재 7건) — entered vs shadow 대조(H13)는 장기 과제.
3. 검증 후: exit 튜닝(H2/I1·I2, winner MFE 반납), regime 게이팅(H3/H9), sizing.
4. ⚠️ **필드 인플레 경계**: 표본 작은데 변수 추가 = 다중비교 함정. 가설 명확한 것만, 표본 먼저. 새 필드 추가 금지(이미 35필드 충분).
