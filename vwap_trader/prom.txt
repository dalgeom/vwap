이 repo는 다른 PC에서 봇을 중단하고 git push 한 상태다. 이 PC에서 재가동 전:

1. **`git pull` 먼저.** `data/state_momentum.json`에 오픈 포지션 3개·bar_counter·cooldown이 들어 있다. pull 안 하면 봇이 옛 상태로 떠서 포지션 추적이 어긋난다.
2. **절대 두 PC에서 동시에 돌리지 말 것.** 같은 Bybit 데모 계좌를 둘이 관리하면 주문 중복·SL 충돌로 망가진다. 이전 PC의 봇이 완전히 죽었는지 먼저 확인.
3. 재가동: `w32tm /resync /force`(관리자) → `.\venv\Scripts\python.exe -m vwap_trader.momentum_bot`
4. 로그에 `State loaded: 3 positions, bar=188...` 뜨는지 확인. 포지션은 Bybit 서버에 살아있으니 봇 꺼진 동안에도 SL은 작동.

## 1. 프로젝트 개요
- **위치**: `vwap_trader/`, Windows + PowerShell, venv `vwap_trader/venv/`. **git root는 한 단계 위(`code/`)**.
- **봇**: Bybit USDT 무기한 선물 **데모 계좌**, 모멘텀 추종.
- **버전 v5.1+**: 1h봉 + BE+Trailing + 1m 폴링 + Tier Cap + Clock Resync + **신호컨텍스트 로깅 + Shadow Log**.
- **핵심 원리**: 1h봉 abs(return)이 과거 500봉 99.5%ile 초과 시 그 방향 진입.
- **현 단계**: 데이터 수집 + 손실 원인 연구. 검증 임계점 50건(첫 평가) / 200건(Go/No-Go).

## 4. 이번 세션 핵심 발견 ★ 가장 중요 (상세 PLAN §8.5)

### 4.1 손실 원인 (473건 분석)
- 패자 **82%가 진입 직후 역행(MFE<0.5%)** = 구조적 adverse selection(신호가 단기 극점 포착).
- **진입 시점 변수(신호세기·변동성·BTC방향·꼬리·거래량)로는 winner/loser 변별 불가.**

### 4.2 조기컷 = 막다른 길 (재시도 금지)
- 인트라바 백테스트(WR 98.7%)는 실전 손실 재현 못 해 검증 불가. 시간 기반 컷은 늦터지는 대박을 죽여 역효과(-$600~800).

### 4.3 변별신호 가설 — "이미 한참 오른 막차=탈진" (38건, 가설 단계)
- 후보: 선행추세 `ret_12/24`, 연속봉 `consec`, OI변화 `oi_chg`(승자 증가/패자 감소 가설).
- **무효(변별력 없음)**: 꼬리, 거래량 spike, 펀딩, 군집.
- ⚠️ **단일 필드 불완전 — 실거래 반례 누적 중**:
  - ALLO: `ret_12=73%`(극단 막차, 가설상 위험 1순위)인데 **+54% 최대 winner**. OI +5.5.
  - BCH: 패자인데 `oi_chg=+9.97`(OI 증가, 가설상 승자 신호). → SL.
  - → OI 부호/ret_12 하나로는 못 거른다. **다변량 + 표본**이 답.

## 5. 이번 세션 코드 변경 (momentum_bot.py + config, 거래로직 무영향)

### 5.1 신호 컨텍스트 5필드 (로깅 전용)
- `signal_ret_6/12/24`(진입 전 N봉 누적수익, 방향 반영 %), `signal_consec`(연속 동방향봉), `signal_oi_chg`(OI 1h 변화율 %).
- `_compute_signal_context()` → OpenPosition → `_log_trade`. 미래 진입부터 기록(소급 X).

### 5.2 Shadow Log ★ 이번 세션 신규 구현 완료
- **목적**: fire 됐지만 진입 안 된 신호 기록 → **생존편향 깨기**(걸린 신호의 가상 성과로 대조군 확보).
- 출력 `data/shadow_momentum.jsonl`, trades와 **동일 스키마**(exit/pnl 제외 + `shadow_reason`). forward 성과는 symbol+timestamp+signal_price로 klines 소급.
- `_log_shadow()` + `_scan_universe` 재구성: 만석도 `scan_only`로 신호 포착, 진입만 skip. reason 9종(max_pos_full/btc_filter/slippage_cooldown/rank_cutoff/long_cap/short_cap/size_invalid/tier_cap/order_failed). 로그 `Scan done: N entries, M shadow,...`.
- **현재 파일 미생성** = 아직 걸린 신호 0건(신호 자체가 희귀 + 포지션 여유 있어 다 진입됨). long 3개 차서 다음 long 신호부터 `long_cap` shadow 예상.
- config `logging.shadow_file: shadow_momentum.jsonl` 추가.

## 6. 미해결/우선순위 (냉철한 순서)

1. **데이터 축적이 1순위.** 봇 돌리며 표본 50건+ → entered vs shadow 비교로 ret/consec/oi 검증. 그 전엔 필터 적용 금지(weak winner 죽임).
2. **rate limit(10006)은 critical 아님으로 결론**(5/29). 거래 실패는 retry로 회복, 네트워크 마비는 랜선 일회성 사고. 단 매 정각 scan 47/51(RL로 4코인 skip)은 shadow의 관측 구멍 → **표본 쌓은 뒤** universe 축소($20M→$50M)로 해소 검토. 지금 손대지 말 것.
3. 검증 후: regime 필터(BCH 역추세 숏 사례), exit 튜닝(winner가 MFE 상당분 반납하는 패턴), sizing.

⚠️ **필드 인플레 경계**: 표본 작은데 변수 많으면 다중비교 함정. 가설 명확한 것만, 표본 먼저.
