## 4. 왜 이런 결정을 했나 (근거 — 전부 `analysis_*.py`로 재현 가능)
1. 방향 분리 집계(일지·보드가 한 번도 안 한 것): 데모 v12 숏 72건 -$53.7 / 롱 97건 +$221.9, 실전 숏 21건 -$58.7 / 롱 20건 -$0.5.
2. BTC 레짐별(`analysis_side_regime.py`): **FLAT 레짐 숏 52건 -$144.7**(건당 -2.78, t=-2.87, 7주 전 주차 손실, 데모 -83.5·실전 -61.2 독립 재현)
   vs DOWN 레짐 숏 41건 +$32.3. 롱은 레짐×신호세기 4칸 전부 이익.
3. 뒤집기 시뮬(`analysis_flip_mirror.py`): 실제 1h봉에 봇 청산규칙 적용(실제 숏 건별 상관 0.96). FLAT 숏 52건을 같은 시점 롱으로 → **+$79.2**
   (데모 +40.5·실전 +38.7). **한계: 이익이 상위 5건(HEMI·AKE·LSK·UAI·JCT)에 집중**, 5건 제외 평균 -$0.16(t=-0.18), 전체 t=+1.34. 수수료·슬리피지·정원 미반영. in-sample.
4. 기각한 수정안(데모·실전 동시 개선 안 아님): 손절거리 상한·비례 축소(데모 -104~-196), 전체 0.5배(데모 -84), 강신호 x1.3 제거, 손절 직후 재진입 차단(n=7).
5. **메인 권고 ≠ 사장님 결정**: 메인은 "숏 막기(H-12) + 뒤집기는 가상 추적"을 권했으나(막기 근거 t=-2.87 > 뒤집기 t=+1.34, 실전 코드 변경 위험),
   사장님이 "뒤집기 풀사이즈 즉시"를 선택. 메인은 이의를 기록하고 이행. 판단은 H-13 forward가 한다.

## 7. 서브 PC 할 일 (우선순위)
1. **pull → 코드 리뷰 → 공식 dist 재빌드.** 메인은 로컬 빌드로 가동 중(규칙 위반이나 사장님 지시). 실전 PC의 exe 교체 절차(앱 종료→dist 교체→재시작)를 사장님과 조율.
   메인은 pull 전 `git checkout -- vwap_trader/dist` 필요.
2. **H-09·H-11 합산 판정 점검.** H-09: 보드 17/20 + 실전 3건 = 20건 도달 가능(실전 3건 -$21.8 / 합산 약 +$6). H-11: 등록 후 데모 4건 +$46.4 + 실전 4건 -$32.0 = 8/10.
   ⚠ 10-19 일지: QUSDT +$31.33은 H-09·H-10·H-11이 **동시에** 겨눈 구간 — 세 캡 중 하나라도 있었다면 줄거나 죽었을 승리(rule#4). H-11 캡 논의 시 이 사례를 반영.
3. **낙폭 경보**: 리포트·앱에 자산/누적손익 선(예 $640) 경보 추가 — 지금은 -$59에서도 '결정 필요: 없습니다'.
4. **일지 개선**: 방향×레짐 분리 집계 추가, `btc_1h_change_pct`는 이미 % 단위(일지가 100배로 오독), 10-05 일지 생성 실패(에이전트가 파일 쓰기 권한 요청 문장만 남김) 원인, 과거 일지 숏 신호 부호 재감사(09-20 일지 자체 정정).
5. **blacklist**: 신규 TradFi 계약이 매일 주문 실패(10-14 실패율 56%). 목록 수동 갱신 대신 `symbolType in {stock, ETF, commodity, forex}` 자동 제외 검토(설계 변경이라 사전 협의).
6. **H-13 중간 점검 스크립트**: 표식 거래 vs 같은 신호 가상 숏 비교를 자동화(`analysis_flip_mirror.py` 확장).
