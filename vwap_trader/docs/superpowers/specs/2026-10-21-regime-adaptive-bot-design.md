# 날씨 적응형 봇 ("그림자 조종사" 시스템) — 설계

- 날짜: 2026-10-21 (설계 대화 10-20 밤)
- 결정자: 사장님 (범위=궁극의 봇 전 노브 연동, 방아쇠=완전 자동, 데이터=외부 지표까지)
- 접근: "그림자 조종사 단계 진화" + 5개월 데이터 사전 스크리닝 (접근 1+2 혼합, 사장님 승인)
- 북극성: 봇이 시장 체제(장)를 스스로 읽고, 체제에 맞게 전략 노브 전부를 스스로 조절하는 완전 자동 봇

## 배경 (왜)

v13 반사실 시뮬(2026-10-20)의 발견: 같은 규칙이 체제에 따라 약과도 독도 된다.
- FLAT 숏 뒤집기(H-13): 9/02 이후 +$233, 그러나 5~7월 소급 시 -$9,476 (그 시대 달러).
- walk-forward 검증: "전날까지 최근 20건의 FLAT 숏에서 뒤집기 우위 평균 > 0 → flip ON"
  규칙이 5~7월 57건 전부 OFF(참사 회피), 8월부터 ON 전환(사람의 10-18 결정보다 2개월 빠름),
  9/02 이후 이득 +$212/+$233 보존. K=10(민감)은 6월 whipsaw로 -$739 — 둔감한 다이얼이 정답.

## 전체 구조 — 3층

```
[관측소 regime engine]   매일(+2단계: 매시간) 날씨 지표 측정 → 상태판 기록 (regime_state.jsonl)
        ↓
[그림자 조종사 shadow pilot]  상태판 → 노브 결정("나라면 이렇게") 기록만. 실행 안 함 (shadow_pilot.jsonl)
        ↓  노브별 forward 게이트 통과 + 사장님 판정
[실권 이양]              그 노브만 봇이 상태판을 직접 읽고 자동 전환. 노브별 롤백 스위치.
```

- 실돈 봇(v13)은 1·2층이 도는 동안 한 줄도 안 바뀐다. H-13 게이트(25건) 오염 없음(실행 불변).
- 모든 노브가 **하나의 관측소**를 공유한다 — 노브마다 지표를 따로 만들지 않는다(검증 부담 합산화).

## 관측소 — 지표 1차 세트

| 지표 | 정의 | 주기 | 출처 |
|---|---|---|---|
| 연속성 다이얼 | 최근 K=20건 FLAT 숏 사건의 뒤집기 우위 평균(%p). 사건=실제 flip 거래(가상 숏은 시뮬) 또는 과거 FLAT 숏 | 매일(00:30) | 자체 기록 + 공개 1h봉 시뮬 |
| 시장 분산 | compute_dispersion (기존) | 기록 중 | trades/shadow 레코드 |
| 급등 브레드스 | 유니버스 중 24h 수익률 ≥ +10% 코인 수 | 2단계(매시간) | 스캔 price/kline |
| 자사 rolling EV | 최근 20건 실거래 pnl 합 (낙폭 경보 pnl_last20 재사용) | 매일 | daily_metrics |
| BTC 레짐 | 기존 분류기 UP/DOWN/FLAT × HIGH/LOW (+UNKNOWN) | 기록 중 | 봇 |
| 펀딩비 중앙값 | 유니버스 fundingRate 중앙값 | 2단계(매시간) | Bybit get_tickers |
| 전체 OI 변화 | 유니버스 openInterest 합의 전시간 대비 변화율 | 2단계(매시간) | Bybit get_tickers |

- 외부 2차 후보(BTC 도미넌스, 공포탐욕지수)는 그림자 조종사가 내부 지표로 못 잡는 전환을 놓치는 것이
  확인될 때 추가한다(외부 API 의존 최소화).
- 시뮬 엔진은 analysis_flip_mirror.py의 bars/sim(SL3.0/BE1.5/트레일2.0/48봉, 상관 0.96 검증)을
  모듈로 승격해 재사용한다. 분석 스크립트와 리포트 파이프라인이 같은 엔진을 쓴다.

## 노브 — 조종사가 돌릴 손잡이 (승격 순서대로)

1. **flip 다이얼** (H-14, 1차 승격 후보): 연속성 다이얼 > 0 → flip ON, ≤ 0 → OFF(숏 유지).
   K=20, 최소 사건 5건 미만이면 판단 보류(현상 유지). walk-forward 검증 완료 축.
2. **숏 정책**: 전면 허용 ↔ DOWN 레짐만 ↔ 추가 제한. 체제 조건은 5개월 스크리닝으로 확정 후 등록.
3. **공격성**: position_pct 배수 0.75x~1.25x를 체제·rolling EV·낙폭 상태에 연동.
   **상한 1.3x(사장님 기수용 한도) 절대 불가침, 낙폭 경보 발화 중 상향 금지.**
4. **게이트 강도**(후순위): 소진·스프레드 임계를 변동성 체제에 연동.

- 정책은 전부 사람이 읽을 수 있는 규칙 테이블(if-then). ML 블랙박스 금지(설명 가능성 = 운영 계약).
- 노브별 구체 임계값: 5개월 데이터 스크리닝으로 후보 선정 → 사전등록에 박제 → 그림자 forward로 증명.

## 그림자 조종사 — 동작과 성적표

- 매일 00:30 리포트 파이프라인에서: 상태판 갱신 → 오늘의 노브 결정 기록 → 어제 발생 거래에 대한
  그림자 손익 계산.
- 그림자 손익: 실제와 방향 같으면 사이즈 비례(정확), 방향 다르면(flip 차이) 시뮬 엔진으로 가상 거래 계산.
- 일일 리포트 신규 섹션 "그림자 조종사": 실제 봇 vs 그림자 누적 비교 + 분기 사건(판단이 달랐던 거래) 목록
  + 어느 노브가 차이를 만들었나.
- 기록: data/<mode>/regime_state.jsonl(상태판), data/<mode>/shadow_pilot.jsonl(결정·그림자 손익).
  demo/real 분리 원칙(mode_paths) 준수.

## 승격 거버넌스

- 노브별 가설 사전등록(H-14=flip 다이얼부터). 게이트: **분기 사건 30건 또는 4주 중 먼저.**
- 게이트 도달 → 리포트가 '결정 필요'에 상정 → **판정은 사장님** (채택 시 해당 노브 실권 이양 = 봇 코드가
  상태판을 읽어 자동 전환, config에 노브별 롤백 스위치).
- 전 노브 이양 완료 = "완전 자동" 완성형. 이양 후에도 상태판·결정 로그는 전부 남긴다(사후 추적).

## 안전장치

- 상태판 결측·API 장애·사건 수 부족 → 보수 기본값 = 현 v13 로컬 설정 그대로 (UNKNOWN 원칙의 확장).
- 공격성 상한 1.3x 불가침 / 하한 0.6x. 낙폭 경보 중 공격성 상향 금지(그림자 결정에도 동일 적용).
- 그림자 단계에서는 봇 거래 로직 무변경. 승격은 한 번에 한 노브.
- config 커밋 금지 규칙 유지 — 노브 스위치의 메인 PC 전달은 prom.txt 절차로.

## 로드맵

- **1단계 (봇 무변경)**: 시뮬 엔진 모듈화 + 연속성 다이얼 + 그림자 조종사 v1(flip 다이얼만)
  + 리포트 섹션 + H-14 사전등록. 리포트 파이프라인(exe 번들)만 변경 — 재빌드·pull 필요하나 거래 로직 0 변경.

- **3단계 (오프라인)**: 5개월 데이터로 노브 2·3 정책 스크리닝 → 그림자 조종사에 추가 + 가설 등록.
- **4단계 (승격)**: 게이트 도달 노브부터 사장님 판정 → 실권 이양 → 반복.
