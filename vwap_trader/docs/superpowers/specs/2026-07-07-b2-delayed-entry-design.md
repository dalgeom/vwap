## 2. 제1원칙

**입력(정본 거래·config)은 읽기 전용. 산출물은 비교 리포트(콘솔) + 선택적 캐시 1개뿐. 거래·주문 API는 일절 호출하지 않는다(공개 klines 조회만). 봇과 동시 실행 안전.**

## 3. 확인 진입 방식 (사용자 확정: "방향만 맞으면 산다")

각 거래를 N분 지연 진입으로 재구성한다. N ∈ **{1, 2, 3, 4, 5}** 전량 스윕(+ 기준선 N=0).

1. 신호(진입)봉 마감 시각 `e_ms`부터 **N번째 1분봉 종가**를 확인 시점 가격으로 본다.
2. **확인 성립** = 그 종가가 신호 방향으로 유리한 쪽(롱: `> entry_price` / 숏: `< entry_price`). 성립 시 **그 종가에 진입**, 진입시각 = `e_ms + N·60000`.
3. **확인 실패**(반대쪽) = **진입 안 함**(스킵). 실제 결과(baseline PnL)를 "안 산 거래"로 별도 집계 → 피한 손실 / 놓친 잭팟 판별.
4. 지연 진입 시 손절 기준 재계산: 새 손절 = `새진입가 ∓ 1.5×ATR`(ATR은 `atr_at_entry` 유지). 본전잠금·추적익절 배수는 그대로.

## 4. 결과 계산 (backtest_be replay 계승)

- 진입한(확인 성립) 거래는 **새 진입가·새 진입시각부터** 봇 스탑로직을 1분봉으로 재생: 초기 SL 1.5×ATR → 본전잠금(이익 1.5×ATR) → 추적익절 2.0×ATR + spike guard → 48h 시한만기 → 창 소진 시 EndWindow(종가). 수수료 왕복 0.11% 차감(net, backtest_be 동일).
- 코드 방식: 코드베이스 관례대로 `backtest_delayed_entry.py`는 **자기완결**(각 backtest_*.py가 replay를 자체 보유하는 기존 패턴 따름). `backtest_be.py`는 무변경 존치. 1분봉은 전용 캐시(§1, 48h 창)에 저장·재활용.
- 조회 창 = `[e_ms, e_ms + 48h]`(now 상한) — 지연 진입이 실제보다 늦게 끝날 수 있어 실제 청산+여유가 아닌 시한만기까지 확보. 캐시가 짧으면 EndWindow로 보수 처리(과대평가 아닌 과소 방향).

## 5. 신뢰 장치 (최우선 — B-1 신기루 재발 방지)

1. **기준선 재현 검증**: N=0(즉시 진입) 되감기가 **실제 거래 PnL을 재현**하는지 먼저 대조(backtest_be의 validation 계승). 130건(수정 이후) 합계 재현율·건당 평균오차·잭팟 top5 포획을 출력. **재현이 크게 어긋나면 지연 진입 숫자는 신뢰 불가로 명시하고 거기서 판정 보류.**
2. **코호트 분리**: 2026-06-04 수정 전(오염)/후(정상)를 나눠, **판정은 수정 후 130건 기준**. 전체 228건은 참고.
3. **고정 경고 문구**: "진입가 변경 시 출구 경로도 바뀌어 완전 재현 불가(§8.9). 방향성 스크리닝일 뿐 — 유망 시 v11 forward A/B로만 확정, 이 숫자로 규칙 직접 변경 금지."

## 6. 집계·출력 (콘솔)

N=0(기준선) 및 N=1..5 각각:
- 진입 건수 / 스킵(안 산) 건수.
- **순효과**: 총 net PnL(진입분) vs 기준선, 승률.
- **즉시역행 구제**: 스킵된 거래 중 실제 손절이었던 건수·금액(= 피한 손실).
- **잭팟 회계**: 실제 top5 승자 중 지연 진입에서 **지킨 것 / 놓친 것(스킵되거나 이익 축소)**, 각 금액 병기.
- 수정 후 130건 기준과 전체 228건 기준을 나란히.
- 최종: N별 "순효과(늘었나/줄었나) + 잭팟 온전한가" 한 줄 판정.

## 7. 오류 처리

- klines 실패/빈 응답 → 해당 거래 제외(집계 모수에서 빼고 카운트 표기), 계속.
- N번째 봉이 창에 없음(초단기 청산 등) → 확인 불가로 스킵 처리(별도 카운트).
- `.env`/API 키 부재 → 즉시 예외 + 안내(기존 스크립트와 동일, 공개 klines라도 인증 클라이언트 사용).

## 8. 테스트 (`tests/test_delayed_entry.py`)

순수 함수(확인 게이트 + replay)를 API 없이 검증:
- ① 확인 게이트 롱: N분 종가가 진입가 위 → 진입(성립), 아래 → 스킵.
- ② 확인 게이트 숏 대칭.
- ③ 지연 진입 후 즉시 SL → 새 진입가 기준 −net, exit=SL.
- ④ 지연 진입 후 본전잠금→추적익절 → 이익, TrailSL.
- ⑤ 스킵 거래의 baseline 결과 보존(피한 손실/놓친 잭팟 회계용).
- ⑥ 기준선 N=0 재현 = replay가 `entry_price`부터 재생 시 손절/시한 로직 일치(backtest_be 동치).
- 실데이터 E2E는 구현 마지막 1회 실행(첫 실행 klines 전량 조회, 수 분 예상)으로 검증.

## 9. 이 작업이 아닌 것 (스코프 경계)

- `backtest_be.py`·`track_shadow.py`·봇·daily_report·거래로직 **무변경**.
- 확인 기준의 다른 변형("일정 폭 이상"·"계속 안 꺾임")은 범위 밖(YAGNI, 유망하면 후속). B그룹 본전잠금(0.75) 변형도 밖.
- 진입 규칙의 실제 변경(v11)은 C 영역 — 이 도구는 **측정만** 한다.
- 차단된(진입 안 한) 신호에는 적용 안 함 — B-1(track_shadow) 담당. B-2는 **실제 진입한 거래**만.

## 10. 리스크 / 롤백 / 한계

- 읽기 전용 + 산출물(콘솔·캐시) → 스크립트·캐시 삭제로 완전 원복, 봇 무영향.
- API 부하는 공개 조회 + sleep으로 기존 백테스트 수준. 주문 경로와 무관해 봇과 동시 실행 안전.
- **핵심 한계**: 진입가가 바뀌면 이후 전 경로가 바뀌어 완전 정밀 재현 불가(§8.9). 표본도 신뢰 코호트 130건으로 얇다. 결과는 **방향성 판단 재료**이지 결론이 아니다 — 도구가 스스로 경고 문구를 출력해 관리(§5-3).
- demo klines 7일 보관 한계로 아주 옛 신호는 조회 실패 가능 → 제외 처리.
