# 매매일지 시스템 설계 (2026-08-03)

## 왜 만드나

지금 리포트의 "자아성찰"은 **글쓰기 과제**다. claude CLI에 오늘 보고서 텍스트 한 덩어리를 주고
3~5문장을 받는다. 도구가 없어 데이터를 조회할 수 없고, 어제 보고서를 읽지 않아 기억이 없다.

결과가 데이터로 증명된다. `reports/backlog.md` 14건 중 6건이 사실상 같은 제안이다.

```
07-22  peak과 실제 청산 손익의 차이를 기록하자
07-25  청산 전 도달한 최고 미실현을 기록하자
07-27  최고 미실현액과 종료 손익 차이를 남기자
07-31  정점 찍은 시각과 청산 시각의 경과 시간
08-01  진입부터 정점까지 걸린 시간
08-02  진입에서 정점까지 걸린 봉 수
```

매일 처음부터 생각하니 매번 같은 결론에 도달한다. 그리고 14건 전부 `[ ]` 미완료 —
검증 조건이 없어 실행할 수도, 판정할 수도 없는 제안이라 쌓이기만 했다.

더 근본적으로, 지금 구조는 **집계 통계**만 본다. 하루 4~5건에 대해 승률·EV를 재고
"유의한가?"를 물으니 매일 "표본이 작다"로 끝난다. 실제로 v11이 1승 19패로 무너지던
8월 2일 성찰도 "계기판 수준으로만 봅니다"로 마무리됐다.

상위 트레이더의 매매일지는 그렇게 쓰지 않는다. **거래 한 건 한 건을 뜯어본다.**
표본이 작아도 개별 사례에서 배운다.

실제로 이번 v11 20건 안에 이런 게 있었다.

```
07-31 04:00  CAP  롱   신호 +8.99%   →  -6.70%  (2봉, 정점 +3.23%)
07-31 17:00  CAP  숏   신호 -10.61%  →  -8.37%  (1봉, 정점 +1.03%)
07-31 20:00  CAP  롱   신호 +10.59%  →  -5.92%  (0봉, 정점 +0.66%)
                                        합계 -21%p
```

같은 코인에서 16시간 동안 롱→숏→롱으로 3연패. MMT도 같은 밤 3시간에 롱·숏·롱.
집계 통계는 "코인 집중도 55%"라고만 말한다. 일지를 썼다면 첫날 보였다.

## 무엇을 만드나

네 부분. **일지가 중심이고 나머지는 일지를 받친다.**

```
                  ┌─────────────────────────┐
   매일 00:30 ───▶│ ① 계기판 (코드, 비용 0) │─── 봇 고장 경보 + 환경 지표
                  └───────────┬─────────────┘
                              │ 재료 제공
                  ┌───────────▼─────────────┐
                  │ ② 매매일지 (claude)      │─── 건별 복기 + 어제 일지 대조
                  └───────────┬─────────────┘
                              │ 2회 이상 반복된 관찰
                  ┌───────────▼─────────────┐
                  │ ③ 패턴 노트              │
                  └───────────┬─────────────┘
                              │ 처방으로 익으면
                  ┌───────────▼─────────────┐
                  │ ④ 가설보드 (소급 검증)   │─── 사장님 채택/기각
                  └─────────────────────────┘
```

### ① 계기판 — 매일, 코드, claude 호출 없음

**경보 지표 (봇 고장 감지)** — 정상이면 값이 안정적이라 거짓 경보가 낮다.

| 지표 | 정상 | 경보선 | 막는 사고 |
|---|---|---|---|
| ATR 정확도 (봇÷재계산, 진입 건별 중앙) | 1.00 | <0.90 or >1.10 | 2026-08-03 캔들캐시 결함 |
| 거래소↔state 포지션 정합 | 일치 | 불일치 | 2026-07-27 고아 포지션 |
| 봉 연속성 (bar 증가 vs 경과시간) | 일치 | 2봉+ 누락 | 봇 다운·스캔 실패 |
| 슬리피지 (일 중앙 / 최악) | ~0% | 0.5% / 2% | 유동성 악화 |
| 주문 실패율 (신호 대비) | ~20% | 40%+ | 거래소 거부 급증 |

**기록 지표 (경보 없음, 일지 재료)** — `data/daily_metrics.jsonl`에 시계열 축적.

급등 크기별 3시간 수익률(5~8% / 8%+), 역행폭 중앙(ATR 배수), 1.5ATR 초과율,
국면 분포, 승률·EV 롤링(7일/30일), 정점 반납폭 중앙, 게이트 차단율(사유별),
BE A/B 분기 속도, 유니버스 크기.

**규칙: 모든 시장 지표는 유니버스 전체 기준으로만 잰다.**
2026-08-03에 진입 종목 13종만 보고 "시장이 변했다"고 결론냈다가, 유니버스 52종으로
재보니 정반대였다(8%+ 3시간 수익률 v10 −0.74% → v11 −0.10%로 **개선**). 진입 종목은
봇이 이익 낸 종목을 사후에 추린 것이라 생존 편향이 들어간다.

### ② 매매일지 — 매일, claude 에이전트

그날 청산된 거래를 **한 건씩** 복기한다. 청산이 없으면 열려 있는 포지션의 경과를 쓴다.

건별로 다루는 것:

- 진입 시점에 이 코인에 무슨 일이 있었나 (가격 경로 · 최근 이 코인 거래 이력 · 동시 보유 포지션 · 국면)
- 규칙이 기대한 것은 무엇이었나
- 실제로 일어난 일
- **왜 어긋났나**
- **이 패턴을 전에도 본 적 있나** ← 어제·그제 일지를 읽고 판단

마지막 항목이 핵심이다. "3일 전 MMT에서 본 것과 같은 모양"이라고 이어붙이는 것이
지금 구조에 없는 유일한 것이고, 6번 중복 제안이 나온 이유다.

**복기 대상은 규칙이지 판단이 아니다.** 인간 트레이더는 재량 판단을 복기하지만
이 봇은 "99.5%ile을 넘었으니까" 외에 진입 이유가 없다. 그래서 일지가 묻는 것은
*"규칙이 이 상황에서 왜 실패했나"* 다. 감정은 못 고쳐도 규칙은 고칠 수 있다.

### ③ 패턴 노트 — `reports/patterns.md`

**두 번 이상 반복된 관찰만** 승격한다. 한 번은 우연, 두 번부터 패턴.

```
P-01 | 최초 07-31 | 재확인 08-01 | 관찰 3건
같은 코인 단기 재진입이 반복 손실로 끝난다
  07-31 CAP  롱→숏→롱 16시간 3연패 (-21%p)
  07-31 MMT  롱→숏→롱 3시간 3연패
  08-01 GIGGLE 반복 진입
```

### ④ 가설보드 — `reports/hypotheses.md`

패턴이 처방으로 익으면 **검증 조건과 함께** 등록한다. 조건 없는 제안은 등록 거부 —
지금 backlog가 죽은 이유가 검증 조건 부재다.

```
H-01 | 등록 08-03 | 상태: 기각(08-04)
내용: 같은 코인 24시간 내 재진입 차단
근거: P-01 (CAP -21%p, MMT 3연패, GIGGLE)
검증: 정본 전체 소급 적용 시 손익이 개선되는가
결과: v11 20건 -$94.96 → -$54.59 (+$40 개선)
      v10 126건 +$6,362 → +$4,077 (**-$2,285 악화**)
      차단됐을 34건에 TAIKO +$1,186(R=12.9) 포함 — v10 잭팟 2건 중 1건이 재진입 거래
판정: 기각. "재진입이 나쁘다"가 아니라 "잭팟 없는 국면에서만 나쁘다"가 맞다.
후속: H-02 등록 (직전 거래가 손실인 코인만 차단)
```

**소급 검증이 이 시스템에서 돈을 지키는 지점이다.** 일지만 있고 검증이 없었다면
8월 4일에 쿨다운을 넣었을 것이고, v10 같은 장이 오면 수익의 36%를 날린다.

채택·기각은 사장님만 한다. 리포트에 "결정이 필요한 것"으로 올라오고,
Claude Code에서 "H-02 채택" 한마디면 config 수정·테스트·빌드·푸시까지 이어진다.

## 안전 설계

**에이전트에 파일 쓰기 권한을 주지 않는다.**

메인 PC는 봇이 `data/*.jsonl`에 실시간으로 쓰는 곳이고, PLAN에 *"봇 켠 채 data/*.jsonl
저장 금지 (append 롤백 사고 2회)"* 규율이 있다.

- 허용: `Read`, `Grep`, `Glob`, 분석용 파이썬 실행
- 금지: `Write`, `Edit` — 도구 목록에서 아예 제외
- 출력: stdout으로 받아 **파이썬 래퍼가** `reports/journal/YYYY-MM-DD.md`에만 저장
- 저장은 tmp + `os.replace` 원자 교체 (기존 `_atomic_write` 재사용)

에이전트가 실수로든 뭐로든 `data/`를 건드릴 수 없다.

**실패해도 사실 리포트는 남는다.** 기존 구조를 그대로 따른다 — 일지 생성이 타임아웃되거나
죽어도 `reports/YYYY-MM-DD.md`는 이미 저장돼 있고, 일지 자리만 비워둔다.

## 일지 프롬프트에 박아둘 규칙

2026-08-03 조사에서 값비싸게 얻은 교훈이다. 같은 함정을 매번 다시 밟지 않도록 명시한다.

1. **표본에 사후 정보가 섞였는지 점검하라.** 봇이 진입한 종목만 보면 생존 편향이 들어간다.
   시장을 말할 때는 유니버스 전체를 봐라.
2. **집계 구간을 최소 2가지로 쪼개 결론이 뒤집히는지 확인하라.** "5% 이상 급등"으로 뭉뚱그렸을 때와
   "5~8% / 8%+"로 나눴을 때 정반대 결론이 나왔다.
3. **"표본이 작다"로 끝내지 마라.** 개별 사례에서 배울 것을 찾고, 판단이 필요하면
   과거 정본에 소급해서 오늘 검정하라.
4. **처방을 낼 때는 이 전략의 수익원이 소수 잭팟이라는 점을 먼저 확인하라.**
   잭팟을 죽이는 규칙은 승률을 올려도 손해다.

## 구현 단계

**1단계 — 매매일지** (가장 가치 큼, 단독으로도 작동)
에이전트 모드 호출 + 어제 일지 로딩 + 건별 복기. 이것만으로 "CAP 3연패"가 첫날 잡힌다.

**2단계 — 패턴 노트 + 가설보드**
반복 관찰 승격, 검증 조건 강제, 과거 소급 검증. 나쁜 아이디어를 걸러 돈을 지키는 단계.

**3단계 — 계기판**
경보 지표 5개 + 기록 지표. 봇 고장 감시.

기존 `backlog.md` 14건은 전부 검증 조건이 없어 죽었다. 살릴 수 있는 것만 패턴/가설로
승격하고 나머지는 `reports/backlog_archive.md`로 내린다.

## 이 시스템이 못 하는 것

- **신호를 새로 발명하지 못한다.** "규칙이 왜 실패했나"를 보지, "어떤 규칙이 돈을 버는가"를
  처음부터 만들지 않는다.
- **없는 엣지를 만들지 못한다.** 이 전략의 t값이 잭팟 2건에 의존한다는 건 이미 나온 사실이고
  (상위 2건 제거 시 t 1.72→1.00), 일지는 그 사실을 더 빨리 보게 할 뿐이다.
- **매일 처방을 내지 않는다.** 패턴 2회 반복 + 소급 검증 + 실거래 재확인을 거치면
  한 달에 두세 번이면 많은 편이다. 매일 처방이 나온다면 그게 오히려 경고 신호다.

## 배포

리포트·일지 코드는 exe에 번들되므로 **서브 PC(DEV_BASIC)에서 빌드**한다.
메인 PC 재빌드 금지 — 8MB 바이너리 충돌(§10 2026-07-30).

```
서브 PC: 개발 → 테스트 → build_exe.ps1 → 커밋·푸시
메인 PC: 봇 정지 → 앱 종료 → git pull → exe 실행 → 봇 시작
```

메인 PC에 claude CLI가 로그인돼 있어야 한다(현재 성찰이 동작 중이므로 충족).
